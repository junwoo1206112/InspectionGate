# 다음 구현 명세 — 실제 로컬 파일 검증

2026-11-09. 사용자가 권장안 선택·구현을 위임했고, Ouroboros 인터뷰 및 A·B·C 검토로 선택했다. 새로운 사용자 답변이나 실제 데이터 사용 승인을 만들어 내지 않는다.

목표: 검토 기록과 로컬 이미지를 받아 실제 파일에서 얻은 증거로 Phase 3 manifest와 그룹 분할을 생성한다.

## 완료 기준

1. 출처·라이선스·버전·취득일 및 reviewer/reviewed_at/intended_use/label_definitions/group_policy/cluster_policy가 필요하다. 기록 존재 검사는 법적 사용권이나 라벨 정확성 판정이 아니다.
2. dataset root 안의 상대 경로만 허용한다. 절대·drive/UNC·상위 이동·외부 링크 경로, 누락, 비파일은 사유로 격리한다. 원본을 이동/삭제하지 않는다.
3. 실제 제한된 bytes의 크기·SHA-256을 계산한다. PNG/JPEG/BMP만 허용하며 verify 후 동일 bytes 재열기/load, 단일 프레임, 기본 20 MiB/25,000,000 pixels 제한을 검사한다.
4. 전역 입력 계약 실패는 출력 생성 전에 중단한다. 행 실패는 정상 행 진행과 제외 기록을 허용한다. 모든 행 제외 시 보고서는 생성하지만 상태 no_valid_samples 및 CLI exit 2로 표시한다.
5. 기존 Phase 3 writer와 그룹 분할을 재사용한다. 파일별 검증 근거, 검토 기록, 설정/버전/입력 해시를 남긴다. 동일 입력·환경·seed에서 재현 가능하며 그룹/해시 교집합을 실제 결과에서 측정한다.
6. 새 결과 디렉터리만 허용하고 dataset root와 출력 경로의 중첩을 거절한다. 생성 이미지 fixture 및 손상/누락/경로/크기/중복/전이 연결/CLI 회귀로 검증한다.
7. 기존 HOLD·사람 결정·모델 부재 503 계약 유지. 평가 not_measured 유지. 실제 공개 데이터 평가, 모델 학습/ONNX/Docker 실행, 자동 근접중복 검출, 적대적 동시 파일 교체 방어는 범위 밖이다.

검증: 전체 pytest 및 생성 이미지 CLI smoke. 공개 제조 데이터 검증으로 표현하지 않는다.
